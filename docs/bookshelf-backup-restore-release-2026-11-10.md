# BookshelfNG backup restore: v0.9.1000 release evidence

- Published ChaptarrNG [v0.9.1000](https://github.com/snapetech-org/chaptarrng/releases/tag/v0.9.1000) from `14920cc642aec7a6b498ae1313d77e4d50a6f0d7` with 35 assets. The [release workflow](https://github.com/snapetech-org/chaptarrng/actions/runs/42905082474) completed successfully on attempt 3. The prior BookshelfNG [v0.4.21.85](https://github.com/snapetech-org/bookshelfng/releases/tag/v0.4.21.85) remains published with 38 assets.
- A backup from BookshelfNG v0.4.21.85 restored normally into published ChaptarrNG v0.9.995 and v0.9.999. A controlled variant with SSL enabled and a certificate path available only on the source reproduced the reported `Non-recoverable failure, waiting for user intervention...` console prompt in v0.9.995. The reporter's actual backup and logs were unavailable, so this establishes one cause of the same symptom, not the cause of that specific report.
- v0.9.1000 rejects an unavailable saved SSL certificate path before staging the backup. A separate post-stage startup failure rolls the restore back and retries startup once with the previous data. Local HTTP checks confirmed the rejected upload returned 400 while the app stayed healthy; forced post-stage failures retained the prior configuration and database and restored `/ping` without the fatal console prompt.
- The first release attempt exposed an M4B worker readiness-file race; `2194a751` fixes the test harness on `main`. The second exposed an 8-second forced-failure window that could expire on macOS before database promotion; `5424f100` gives that installed rollback test 30 seconds on `main`. Both failed checks passed on targeted retries against the unchanged release tag. The latter fix is test-only and follows the release commit.
- Release destination verification and the Discord announcement job passed. The [changelog announcement](https://discord.com/channels/1447333772419928256/1569406962800656495/1569869099062923316) went to the owner-selected ChaptarrNG release channel, with a [project-channel pointer](https://discord.com/channels/1447333772419928256/1552357772975280199/1569869100534997094).
- Private backup variants, source data, and failure logs remain in task-owned scratch on `kspld0` at `/tmp/chaptarrng-backup-repro-20261110/`. Do not commit or publish the backup contents.
